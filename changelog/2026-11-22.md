## Upgrading an existing installation

| Service | Setting | Value |
| --- | --- | --- |
| Postgres Meta | Source image | `supabase/postgres-meta:v0.100.0` |
| Imgproxy | Source image | `darthsim/imgproxy:v4.0.21` |
| Envoy | `SUPABASE_PUBLIC_URL` | `${{"Supabase Studio".SUPABASE_PUBLIC_URL}}` |
| Supabase Realtime | `RELEASE_COOKIE` | `${{secret(28)}}` (Generate a secret) |
| Supabase Realtime | `GEN_RPC_SOCKET_IP` | `127.0.0.1` |
| Supabase Realtime | `CLUSTER_STRATEGIES` | ` ` (Space character) |

1. **Back up Postgres before redeploying Storage.** The Storage update runs a one-way schema migration. Rolling back the Storage image alone cannot undo it. If the database ever ran Storage `v1.72.0` through `v1.72.3`, review the upstream repair before upgrading. [Storage upgrade notes](https://github.com/supabase/supabase/releases/tag/self-hosted/v0.8.3) · [Storage repair](https://github.com/supabase/storage/issues/1394)
2. Apply the Railway settings above to the existing project.
3. Update the template and deploy the staged changes. For an existing database, separately remove the stored `app.settings.jwt_secret` after checking for dependent SQL. Where Database Webhooks are installed, grant `supabase_functions_admin` `USAGE` on the `extensions` schema. [JWT setting patch](https://github.com/supabase/supabase/pull/45003) · [Database Webhooks patch](https://github.com/supabase/supabase/pull/46526)
